Deliveries that fail with a 5xx or time out should retry with exponential backoff: 30s, then doubling, six attempts in total. Merchants see each attempt in the dashboard.

Acceptance criteria

#1 Retries follow 30s, 1m, 2m, 4m, 8m, 16m with ±20% jitter
#2 4xx stops retrying, except 408 and 429
#3 A 429 waits for Retry-After and doesn't use an attempt
#4 The dashboard lists every attempt with its status code

Definition of done

#1 Tests pass in CI
#2 Merchant docs updated

Implementation plan

  • Move delivery into a pg-boss job with retryLimit: 6
  • Compute the delay in nextDelay(attempt, retryAfter)
  • Store attempts in webhook_attempt

Implementation notes

pg-boss retryBackoff doubles from retryDelay, so the 30s base works without custom code. Jitter is ours.

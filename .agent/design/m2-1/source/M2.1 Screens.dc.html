M2.1 screens · repository link

A project can be linked to one git repository so the pm CLI finds the project inside a clone. Three places change: the projects table, the New project dialog and the Edit project dialog. Ledger direction, no new tokens. The M1 and M2 screens live in their own canvases.

Rules kept

  • Repository text uses the mono 10.5px faint style already used for keys and dates. It turns accent and underlined on hover, like every other link.
  • The short form drops the protocol, user and .git: gitlab.com/reddevs/payments. The link opens https://host/path in a new tab and never opens the project row.
  • Long paths are cut from the left, so the repository name at the end stays visible. The full URL shows on hover.
  • No provider logos: the same instance may use GitHub, GitLab, Gitea or Forgejo.

Calls I made on the brief

  • Repository sits last in both dialogs, after Description, because it is optional and most people fill it later or with pm link.
  • Under a filled field, the hint shows the short form the URL matches, so an SSH paste reads back the same as the table.
  • Format errors show as you leave the field; the conflict shows after submit and names the project that has the repository.
  • Clearing the field in Edit project says what saving will do instead of asking for confirmation.

Recommendation: 1a

Rows keep their 52px height and the table keeps its columns, so nothing changes at 1024px. The repository joins the other secondary text of the row.

Runner-up: 1c, if scanning repositories down a column matters more than width. It takes 210px from the project name and would hide below about 1180px.

1b adds 12px to every row, linked or not. 1d makes long names truncate sooner and puts two kinds of text on the name line.
